# LG TUNE 기술 명세서 v1

기준일: 2026-11-25 · 작성: 백엔드(김진혁) · 대상: 팀 전원, 심사 "기술 디펜스" 대비
서비스 정의: **TV에 사는 내 친구. 같이 보고, 같이 본 걸 기억해서 먼저 꺼내는 단짝.**
이 문서는 학교 설계 산출물 5종(요구사항 정의서, 화면설계서, 시스템 아키텍처, DB 요구사항 분석서, AI 기능 구현 명세서)으로 바로 나눌 수 있게 구성했다.

## 0. 한 장 요약

### 무엇을 만드나
시연용 MVP가 아니라 **"LG TV에 그대로 옮길 수 있는 구조로 만든 작동 제품"**. 화면은 노트북이 TV 역할을 한다.

### 핵심 결정 10개

| # | 결정 | 이유 (기술 디펜스용 한 줄) |
| --- | --- | --- |
| 1 | 노트북 = TV, 방송은 **가상 채널**(직접 만든 영상 + 자막) | 셋톱 출력은 보통 HDCP로 보호돼 노트북 캡처 장치로 받을 수 없음(§6.3) |
| 2 | 백엔드 **Python 3.11 + FastAPI**, 프론트 **React + Vite + TypeScript** | 음성·AI 라이브러리가 전부 Python. 프론트는 TV 웹앱(webOS도 웹 기반)과 같은 방식 |
| 3 | DB는 **SQLite 한 파일** (+ sqlite-vec 벡터, FTS5 전문검색) | 기억은 기기 안에 둔다는 원칙. 서버 DB 비용 0. TV에도 그대로 들어감 |
| 4 | 편성은 **규칙 + 점수 + 밴딧(반응 학습)**, LLM은 말투만 | 결과가 매번 같아야 하고, 칸마다 "고른 이유"를 설명할 수 있어야 함 |
| 5 | 대화 LLM은 **Claude Haiku 5.5**, 밤 기억 정리는 **Claude Sonnet 5.5 배치** | 턴당 비용이 매우 낮고(§7.4), 정리 작업은 실시간이 아니라 배치 50% 할인 |
| 6 | 예비 LLM: **QWENS OR EXAONE → GPT** 자동 전환 | Max 크레딧이 떨어지면 API가 멈춤. 견고성 점수(심사 9번) |
| 7 | 직접 학습하는 모델 3개: **호출어("(호출어 미정)")**, **응/아니 분류기**, **STT 노인 음성 미세조정(선택)** | "AI를 끼워 넣은 게 아니라 필요한 곳에 학습해서 씀"을 보여 줌 |
| 8 | 임베딩 **KURE-v1**(한국어 검색 특화), TTS **Supertonic 3**(온디바이스) 우선 검토 | 둘 다 로컬 실행 가능 → 음성·기억이 기기 밖으로 덜 나감 |
| 9 | 카테고리 모듈 3개: **드라마 인물 관계도 / 종교 구절 찾기 / 좋아하는 가수 공연 일정** | 데이터를 합법적으로 확보할 수 있는 것만 고름(§5) |
| 10 | 모든 행동을 이벤트로 기록 → **Performance Tracker 대시보드** | 심사 11번: 지표 정의 + 서비스 안에서 실제 수집 |

### AI를 쓰는 곳 / 안 쓰는 곳

| 기능 | 방식 | 왜 |
| --- | --- | --- |
| 편성 점수, 시간 실행, 개입 단계, 예외 규칙 | **규칙** | 틀리면 안 되고 설명 가능해야 함 |
| 편성 가중치 조정 | **밴딧(통계)** | 응/아니 데이터가 적어도 작동. 딥러닝 불필요 |
| 호출어 감지 | **직접 학습한 소형 신경망** | 이름 부를 때만 듣는 원칙을 기기 안에서 구현 |
| 음성 → 글자 | **Whisper 계열 + (선택) 노인 음성 LoRA** | 사람이 규칙으로 만들 수 없는 영역 |
| 응/아니 판별 | **직접 학습한 분류기**, 애매할 때만 LLM | 매 턴 LLM 호출은 과용이고 느림 |
| 대화 생성 | **LLM (Haiku)** | 친구의 핵심 가치 |
| 기억 추출·요약·감정 표시·중요도 | **LLM (Sonnet, 밤 배치)** | 말에서 의미를 뽑는 일. 실시간 아님 |
| 기억 검색 | **임베딩(KURE) + 키워드 + 최근성 점수** | 의미 검색과 정확 검색을 함께 |
| 언제 기억을 꺼낼지 | **규칙** (빈도 제한·상황 조건) | 너무 자주 꺼내면 부담. 통제가 필요 |
| 성경 구절 위치 찾기 | **임베딩 유사도 + 글자 n-gram** | 자막 문장 → 구절 번호. 규칙으로는 불가능 |
| 음성 합성 | **학습된 TTS 모델** | |

### 1.1 기능 요구사항 (우선순위 P0 = 시연 필수)

| F02 | 편성 실행 | 시간이 되면 10분 전 알림 → 채널 자동 전환 (가만히 있으면 진행, "아니"면 취소) | P0 |
| F03 | 응/아니 수정 | "9시 드라마도 넣을까요?" → "아니" → 즉시 재편성 | P0 |
| F04 | 호출어 듣기 | "(호출어 미정)"로 부를 때, 또는 단짝이 물은 뒤 8초만 들음. 그 밖에는 듣지 않음 | P0 |
| F05 | 같이 보기 대화 | 방송 중엔 먼저 말하지 않음. 광고·방송 끝에만 한마디. 부르면 대답 | P0 |
| F06 | 기억 쌓기 | 대화·반응·시청을 사건으로 저장 → 밤에 기억 카드로 정리 | P0 |
| F07 | 기억 꺼내기 | 관련 순간에 "지난주 좋다고 하신 그 배우 오늘 나와요" | P0 |
| F08 | 잊어 줘 | "(호출어), 그건 잊어 줘" → 해당 기억 삭제 | P0 |
| F09 | 첫 설정 (자녀 폰) | 부모님 호칭, 기상·취침 시간, 즐겨 보는 프로그램 3개, 좋아하는 가수 | P0 |
| F10 | 취향 맞히기 놀이 | 첫날 10분, 응/아니·둘 중 하나로 취향 수집 (콜드 스타트) | P1 |
| F11 | 인물 관계도 | "저 사람 누구야?" → 해당 드라마 인물 관계도 카드 | P0 |
| F12 | 구절 찾기 | 설교 자막에서 성경 구절 위치와 본문을 큰 글씨로 | P1 |
| F13 | 공연 일정 알림 | 좋아하는 가수 공연이 생기면 광고 시간에 알림 (예매는 안 함) | P1 |
| F14 | 잠든 것 감지 | 물어도 두 번 대답 없으면 자동 전환 중지 + 꺼짐 예약 | P0 |
| F15 | 직접 조작 존중 | 사용자가 채널을 바꾼 직후엔 자동 전환하지 않음 | P0 |
| F16 | Performance Tracker | 지표 실시간 대시보드 (§8) | P0 |
| F17 | 가수 목소리 팩 | 고정 멘트를 다른 목소리로 (구조만, 가상 목소리) | P2 |

### 1.2 비기능 요구사항

| 항목 | 목표 | 측정 |
| --- | --- | --- |

## 2. 시스템 아키텍처

### 2.1 전체 구성 (시연 = 노트북 한 대)

```
┌──────────────────────── 노트북 (TV 역할) ────────────────────────┐
│                                                                  │
│  [브라우저 전체화면 - TV 웹앱 (React)]                             │
│   ├ 가상 채널 플레이어 (영상 + 자막 .vtt)                           │
│   ├ 오버레이: 하루 편성표 / 단짝 말풍선 / 인물 관계도 / 구절 카드     │
│   └ WebSocket ⇄ 백엔드                                            │
│                                                                  │
│  [FastAPI 백엔드 (Python)]                                        │
│   ├ ① 시계·스케줄러 (APScheduler, 시연용 시간 가속)                  │
│   ├ ② 편성 엔진 (규칙+점수+밴딧)                                    │
│   ├ ③ 재생 제어기 ── 어댑터: 가상채널 | (제품) 셋톱 API·IR·CEC       │
│   ├ ④ 음성 파이프라인: 마이크 → VAD → 호출어 → STT → 정규화 → 의도   │
│   ├ ⑤ 대화 관리자: 말할 타이밍 판단, 맥락 조립                      │
│   ├ ⑥ 기억 서비스: 사건 기록 → 밤 정리 → 검색 → 꺼내기 → 잊기        │
│   ├ ⑦ 카테고리 모듈: 인물관계도 / 구절찾기 / 공연일정                │
│   ├ ⑧ TTS: 고정 멘트 캐시 + 실시간 합성                             │
│   ├ ⑨ LLM 게이트웨이: Claude → EXAONE → GPT 순서로 전환             │
│   └ ⑩ 지표 수집기 → 대시보드                                       │
│                                                                  │
│  [SQLite: tune.db]  기억·편성·로그 (sqlite-vec, FTS5)               │
│  [로컬 모델]  호출어 · 응/아니 분류기 · STT · 임베딩 · TTS            │
└──────────────────────────────────────────────────────────────────┘
        │ HTTPS (필요한 기억 몇 개 + 현재 발화만)
        ▼
  [클라우드 LLM]  Claude API / EXAONE API / OpenAI API
  [공공 API]      KOPIS 공연 정보 (하루 1회 동기화)

  [자녀 폰 브라우저] 첫 설정 페이지 (같은 FastAPI가 제공)
```

### 2.2 이벤트 흐름 예시: "가요무대 10분 전"

```
스케줄러 19:50 ─▶ 편성 엔진: 오늘 plan_item(가요무대, 20:00) 확인
              ─▶ 대화 관리자: 지금 말해도 되는가? (방송 중이면 다음 경계까지 대기)
              ─▶ 기억 서비스: 관련 기억 검색 ("지난주 가요무대에서 ○○ 노래 좋다고 함")
              ─▶ LLM(Haiku): 한 문장 생성 / 실패 시 고정 멘트
              ─▶ TTS ─▶ 프론트: 말풍선 + 음성
              ─▶ 듣기 창 8초 열림 ─▶ "아니" 감지(분류기) ─▶ plan_item 취소 + 반응 기록
                                  └▶ 무응답 ─▶ 20:00 재생 제어기: 채널 전환
              ─▶ 지표 수집기: proposal, response, latency 기록
```

### 2.3 제품 단계 매핑 (LG TV로 옮길 때)

| 모듈 | 시연 (노트북) | 제품 (LG TV + 클라우드) |
| --- | --- | --- |
| TV 웹앱 | React (브라우저) | webOS 웹앱 (같은 코드 기반) |
| 재생 제어 | 가상 채널 | 그룹사 셋톱 연동 API / IR / HDMI-CEC 어댑터 |
| 편성 정보 | 직접 만든 EPG JSON | 셋톱·방송 EPG + 메타데이터 제휴 (§5.1) |
| 호출어·VAD·응/아니 분류 | 로컬 Python | TV 온디바이스 (ONNX) |
| STT | 로컬 Whisper | 온디바이스 소형 모델 또는 LG 서버 |
| 기억 DB | SQLite 파일 | TV 저장소 SQLite + 동의 시 종단간 암호화 백업 |
| LLM | Claude API | LG 서버 경유 (EXAONE 등) / 온디바이스 sLM |
| TTS | 로컬 ONNX | 온디바이스 + 고정 멘트 사전 합성 |

**설계 원칙: 모든 외부 의존(재생 제어, LLM, STT, TTS)은 어댑터 인터페이스 뒤에 둔다.** 시연과 제품의 차이는 어댑터 교체뿐이다.

## 3. AI 기능 구현 명세

각 AI 기능을 **입력 → 처리 → 출력 → 평가 → 실패 시 대응**으로 정리한다.

### 3.1 호출어 감지 ("(호출어 미정)") — 직접 학습

| 항목 | 내용 |
| --- | --- |
| 입력 | 마이크 16kHz 스트림 (80ms 단위) |
| 모델 | openWakeWord 계열 소형 분류기. 학습 파이프라인은 [livekit-wakeword](https://github.com/livekit/livekit-wakeword) 우선 검토 (openWakeWord 호환, 합성 데이터 생성→증강→학습→내보내기 한 번에) |
| 학습 데이터 | ① TTS로 만든 "(호출어 미정)" 수천 개 (여러 목소리·속도·높이) ② 팀원·가족 실제 녹음 ③ 부정 데이터: TV 소리, 일상 대화, "AI 친구"가 아닌 비슷한 말 |
| 근거 | 한국어 호출어를 openWakeWord로 학습하고 TTS 합성 데이터로 증강한 연구가 있음 ([arXiv 2501.12194](https://arxiv.org/abs/2501.12194)). 합성 데이터만으로 F1 0.91을 낸 비영어 사례도 있음 ([논문](https://pequi-mecanico-home.github.io/pdf/paper_wakeword.pdf)) |
| 출력 | 감지 점수 → 임계값 넘으면 "듣기 창" 열기 |
| 평가 | 오탐 시간당 0.5회 미만(실제 제품 통상 기준, [livekit-wakeword](https://pypi.org/project/livekit-wakeword/)), 인식률 90% 이상 |
| 실패 대응 | 두 번 못 알아들으면 화면에 "리모컨 확인 버튼을 눌러 주세요" |
| 개인정보 | 호출어 감지 전 음성은 메모리에서만 흐르고 저장하지 않음 |

### 3.2 음성 → 글자 (STT)

| 항목 | 내용 |
| --- | --- |
| 기본 | faster-whisper (large-v3-turbo 또는 small, 노트북 사양 보고 결정) |
| 선택: 노인 음성 미세조정 | Whisper + **LoRA**. 소량 데이터에서 LoRA가 전체 학습보다 안정적이라는 연구가 있음 ([Interspeech 2025](https://www.isca-archive.org/interspeech_2025/park25g_interspeech.html)) |
| 학습 데이터 후보 | 한국어 노인 음성 데이터셋 **VOTE400**(노인 돌봄 대화용 400시간, [논문에서 사용](https://arxiv.org/pdf/2604.24770)) / AI Hub 노인 음성 데이터 (**정확한 데이터셋명·신청 조건 확인 필요**). AI Hub 데이터로 만든 모델은 출처를 밝히면 배포·상업 활용 가능, 데이터 재배포는 불가 ([공공데이터포털 안내](https://www.data.go.kr/data/15146382/fileData.do)) |
| 증강 근거 | LLM으로 노인 말투 문장을 만들고 TTS로 합성해 추가 학습하면 70세 이상 음성에서 Whisper 기본 대비 **WER 최대 58.2% 감소** ([IEEE SPL 2026](https://signalprocessingsociety.org/index%2ephp/publications-resources/ieee-signal-processing-letters/2026/10/elderly-contextual-data-augmentation-speech-synthesis-elderly-asr)) |
| 학습 환경 | Colab 유료 GPU (학교 지원 항목) |
| 후처리 | **어르신 발화 정규화 사전**: "테레비→TV", "가요무데→가요무대", 프로그램명·인물명 사전으로 교정 |
| 평가 | 팀 가족 어르신 녹음 100문장으로 **CER: 기본 vs 미세조정** 비교 (심사 발표용 수치) |
| 실패 대응 | 신뢰도 낮으면 "다시 한번 말씀해 주시겠어요?" 1회 → 두 번째 실패 시 화면 선택지 |

### 3.3 응/아니 분류기 — 직접 학습

| 항목 | 내용 |
| --- | --- |
| 목적 | 단짝이 물은 뒤 대답을 **응 / 아니 / 애매 / 다른 말** 4개로 분류 |
| 모델 | 한국어 소형 인코더(KLUE-RoBERTa 계열) 파인튜닝. CPU 추론 수십 ms |
| 데이터 | ① LLM으로 어르신 말투 변형 3~5천 문장 생성 ("그려", "됐어", "아이고 좋지", "그건 좀…") ② 팀원·가족 실제 녹음을 STT로 받은 문장 (검증셋) |
| 규칙 | "애매" 또는 신뢰도 0.7 미만 → LLM에 한 번 물음. "다른 말" → 대화로 넘김 |
| 평가 | 실제 녹음 검증셋 F1 0.9 이상. **"분류기만 / LLM만 / 혼합"의 정확도·지연·비용 비교표**를 발표에 사용 |

### 3.5 기억 시스템 (핵심 차별점)

**목표: "검색해서 답하는 챗봇"이 아니라 "같이 본 걸 기억하는 친구"**

#### 기억 3단 구조
| 층 | 내용 | 언제 만들어지나 |
| --- | --- | --- |
| ① 사건 로그 | 시청, 응/아니, 대화 한 턴을 시간순으로 그대로 | 실시간 |
| ② 에피소드 | "11/24 저녁 가요무대를 같이 봄. ○○ 노래에 '아이고 좋다' 하심. 기분 좋아 보임" | 밤 정리(배치) |
| ③ 기억 카드 | 오래 가는 사실: 취향 / 사람 / 약속 / 이야기 / 말투·성격 | 밤 정리(배치), 같은 내용은 합침 |

#### 밤 정리 (매일 새벽 3시, Sonnet 5.5 배치)
1. 그날 사건 로그 → 에피소드 3~10개로 요약 (감정, 중요도 1~5 포함)
2. 기존 기억 카드와 비교 → 추가 / 갱신 / 모순 표시
3. 임베딩(KURE-v1) 계산 → sqlite-vec에 저장
4. 3일 지난 대화 원문 삭제 (요약만 남김)

#### 기억 검색 점수
```
점수 = 0.5 × 의미 유사도(KURE 임베딩)
     + 0.2 × 키워드 일치(FTS5: 프로그램명·인물명)
     + 0.2 × 중요도
     + 0.1 × 최근성(오래될수록 감소)
     − 최근에 이미 꺼낸 기억이면 감점
```
한국어 검색에서 KURE-v1은 bge-m3를 한국어로 미세조정한 1024차원 모델이고 MIT 라이선스라 로컬 사용 가능 ([Hugging Face](https://huggingface.co/nlpai-lab/KURE-v1)).

#### 기억 꺼내기 규칙 (먼저 말할 때)
| 규칙 | 값 |
| --- | --- |
| 같은 기억 재사용 간격 | 최소 3일 |
| 하루 먼저 꺼내는 기억 | 최대 2개 |
| 꺼내는 순간 | 관련 프로그램 시작 전 / 관련 인물 등장 회차 / 기념일 |
| 슬픈 기억 | 사용자가 먼저 말하기 전엔 꺼내지 않음 |
| 반응 기록 | 꺼낸 뒤 반응(긍정/무응답/부정)을 저장 → 다음 꺼내기 판단과 지표에 사용 |

#### 잊기
"그건 잊어 줘" → 최근 대화 주제와 가장 가까운 기억 카드 1~3개를 화면에 보여 주고 "이거 지울까요?" → "응" → 카드·관련 에피소드·임베딩 삭제.

### 3.6 편성 엔진 (규칙 + 점수 + 밴딧)

```
점수(프로그램) = w1×취향 일치 + w2×반응 기록 + w3×시간 습관 + w4×새로움
초기 가중치 = 0.4 / 0.3 / 0.2 / 0.1
```
| 단계 | 내용 |
| --- | --- |
| 후보 | 오늘 EPG에서 기상~취침 사이 프로그램 |
| 하드 규칙 | 약속 시간 제외, 취침 30분 전 이후 제외, 같은 시간 겹치면 낮은 쪽은 다시보기 제안 |
| 콜드 스타트 | 자녀가 고른 3개 + 취향 맞히기 결과 + 시간대 기본값. 첫 주는 새로움 비중을 높여 탐색 |
| 학습 | 응=+1, 아니=−1, 끝까지 봄=+0.5, 중간에 채널 바꿈=−0.5 → **장르·시간대별 베타 분포(톰슨 샘플링)** 갱신 |
| 설명 | 칸마다 "고른 이유" 한 줄 (규칙에서 생성, LLM은 말투만 다듬음) |
| 시연 포인트 | **1일차 vs 7일차 편성표 비교 화면** + 심사위원이 즉석에서 "그 드라마 싫어" → 다음 날 편성에서 실제로 빠짐 |

### 3.7 카테고리 모듈

| 모듈 | 처리 | AI 여부 |
| --- | --- | --- |
| 인물 관계도 | "저 사람 누구야?" → 현재 프로그램 + 회차 → 인물 관계 JSON → 관계도 카드 | 규칙 (질문 이해만 LLM) |
| 구절 찾기 | 설교 자막 문장(직전 30초) → ① "○장 ○절" 패턴이면 그대로 ② 없으면 개역한글 전체 구절과 임베딩 유사도 + 글자 n-gram 비교 → 상위 1개 신뢰도 0.8 이상일 때만 표시 | **임베딩 검색** |
| 공연 일정 | 좋아하는 가수 이름 → KOPIS 공연 목록(대중음악)에서 출연진 일치 공연 → 광고 시간에 알림 | 규칙 (이름 표기 흔들림만 정규화) |

### 4.2 용량 추정 (가정)
대화 원문은 3일만 보관하고, 기억 카드·에피소드·임베딩을 합쳐 1년에 수십 MB 수준이다. TV 저장 공간에 충분히 들어가고 **서버 저장 비용은 없다**. 비용이 드는 곳은 저장이 아니라 LLM 호출이다(§7.4).

| AI | anthropic SDK, transformers(분류기), sentence-transformers(KURE) |
| DB | sqlite3 + sqlite-vec + FTS5 (Windows Python의 확장 로딩 지원 여부 먼저 확인) |
| 프론트 | Node 20, React + Vite + TypeScript, WebSocket |
| 품질 | pytest, ruff, pre-commit. 핵심 로직(편성 엔진, 기억 점수, 분류 규칙)은 테스트 먼저 |
| 비밀값 | `.env` (Git 제외). 키는 백엔드에만, 프론트에는 절대 두지 않음 |

### 6.2 저장소 구조 (모노레포)
```
lg-tune/
├ backend/
│  ├ app/ (api, ws, scheduler, plan_engine, voice, dialogue, memory, modules, llm, tts, metrics)
│  ├ adapters/ (playback_virtual.py, playback_settop.py, llm_claude.py, llm_exaone.py ...)
│  ├ db/ (schema.sql, migrations/)
│  └ tests/
├ frontend/ (tv-app, child-setup, dashboard)
├ ml/ (wakeword/, yesno/, stt_lora/ — 학습 노트북과 평가 스크립트)
├ data/ (epg/, cast/, bible/, phrases/)  ※ 학습 데이터 원본은 Git에 넣지 않음
└ docs/ (이 명세서, ADR=결정 기록)
```

### 6.3 셋톱 연동의 현실 (중요)
- 노트북 HDMI 단자는 보통 출력 전용이라 셋톱 화면을 받으려면 USB HDMI 캡처 장치가 필요함 (UVC 장치라 웹캠처럼 인식, [Elgato 설명](https://www.elgato.com/ww/ko/explorer/products/capture/capture-card-acronyms-what-they-mean-and-why-they-matter/))
- **하지만 일반 캡처 장치는 HDCP로 보호된 신호를 보여 주지 않음** (예: [AVerMedia 제품 안내](https://www.avermedia.com/KR/product-detail/GC553)). 유료방송 셋톱 출력은 보호되는 경우가 많아 **화면이 검게 나올 가능성이 높음**
- 결론: **시연 본편은 가상 채널.** 셋톱 채널 제어 가능성은 팀원 집 LG TV + 셋톱으로 IR/CEC 채널 전환을 따로 촬영해 보조 증거로 제시

### 6.4 실행 구성
- 시연: 노트북에서 `backend`(uvicorn) + `frontend`(빌드된 정적 파일을 FastAPI가 제공) → 브라우저 전체화면
- 마이크: 노트북 내장 마이크 기본, 소음이 크면 USB 마이크(하드웨어 지원 신청) / 폰 마이크(WebSocket 오디오) 예비
- 네트워크: 행사장 와이파이 + 폰 핫스팟 예비. 인터넷이 끊기면 편성·고정 멘트·응/아니는 계속 동작

## 7. LLM 운용

### 7.1 모델 배치
| 용도 | 모델 | 이유 |
| --- | --- | --- |
| 실시간 대화, 애매한 응/아니 | Claude Haiku 5.5 | 빠르고 저렴 |
| 밤 기억 정리 | Claude Sonnet 5.5 (Batch API) | 요약 품질 + 배치 50% 할인 |
| 예비 1 | EXAONE API | LG 자산, 무료 API는 비상업·입력 학습 가능 조건 → **가상 프로필만** |
| 예비 2 | OpenAI API | 팀 보유 |

### 7.2 게이트웨이 규칙
타임아웃 3초 → 다음 모델. 모든 호출을 `llm_calls`에 기록(모델, 토큰, 비용, 지연). 하루 예산 상한을 넘으면 고정 멘트 모드.

### 7.3 Max 크레딧
Max 5x는 매월 Claude API 크레딧 $100가 제공되고, Claude Code에는 쓸 수 없으며, 남은 크레딧은 이월되지 않고, 소진되면 API 요청이 멈춤 ([Anthropic 문서](https://platform.claude.com/docs/en/about-claude/api-credits-for-subscribers)). claude.ai 결제 설정에서 Console 조직을 연결해야 받을 수 있음.

### 7.4 비용 추정 (가정)
가격: Haiku 5.5 입력 $0.10 / 출력 $0.50 (100만 토큰당, 10만 토큰 이하 프롬프트), Sonnet 5.5 $2 / $10, 배치 50% 할인 ([가격](https://platform.claude.com/docs/en/about-claude/pricing)).

| 질문 | 답 |

| 왜 편성에 LLM을 안 쓰나 | 매번 같은 결과와 이유 설명이 필요. LLM은 말투만. 학습은 밴딧으로 충분 |
