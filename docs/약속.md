# 0단계 약속: DB · API · 공통 샘플 (초안)

> 마이모드 개발 정리(@연상, 11/26) 기준. **바꾸려면 PR로, 3명 모두 확인.**
> 원본 코드: DB = `backend/app/models/db.py` · API 모양 = `backend/app/contracts/rest.py`

## 1. 시간 표기
- 전부 **한국 시간**, 시간대 표기 없이 `2026-12-01T20:30:00`
- 시연 기준일: **2026-12-01(화)**. 시청 기록은 그 전 14일 (11/17~11/30)

## 2. DB 표 (SQLite + SQLAlchemy)
| 표 | 한 줄 = | 주요 칸 | 채우는 사람 |
| --- | --- | --- | --- |
| `channels` | 채널 | `id`(예: KBS1), `number`(리모컨 번호), `name` | A |
| `programs` | 방송 한 편 | `channel_id`, `title`, `series_key`(회차 묶음), `genre`, `start`, `end`, `cast`(출연자 목록), `is_new`(새 회차), `is_live`(생방송) | A |
| `seniors` | 어르신 한 명 | `age`, `wake_time`, `sleep_time`, `pref_source`(child/self/age_default), `seed_prefs`({series, cast, genres}), `family_picks`(가족 추천 series_key) | A (가족 화면) |
| `watch_logs` | 시청 기록 한 건 | `senior_id`, `series_key`, `genre`, `cast`, `channel_id`, `started_at`, `watched_min`, `feedback`(none/next/help) | C (TV 화면) |
| `plan_items` | 하루표 한 칸 | `senior_id`, `date`, `program_id`, `score`, `reason`, `kind`(pick/fill) | B |

- `feedback`: `next` = "다음에"(−0.3), `help` = "됐다/그만"(−0.5)
- `pref_source` 우선순위: 자녀 입력(child) > 본인 선택(self) > 나이대 기본값(age_default)

## 3. 공통 샘플 (`data/sample/`)
| 파일 | 내용 |
| --- | --- |
| `channels.json` | 채널 6개 (번호는 예시) |
| `programs.json` | 12/1 하루치 편성 92편. 채널마다 05:00~24:00 빈틈·겹침 없음 |
| `seniors.json` | 가상 어르신 3명: s1 김영숙(자녀 입력·트로트/드라마), s2 박철수(본인 선택·뉴스/사극), s3 이순자(기록 거의 없음 = 콜드 스타트) |
| `watch_logs.json` | 14일치 시청 기록 116건. 5분 미만 기록, "다음에"/"됐다" 반응 포함 |
| `schedule_example.json` | 하루표 API 응답 **예시** (s1). 엔진 결과 아님 — 모양 약속용 |

- 방송 이름·출연자는 **전부 가상**. 실제 편성표는 A가 1단계에서 넣음
- 다시 만들기: `cd backend && uv run python scripts/make_sample.py`
- 개발 DB에 넣기: `cd backend && uv run python scripts/load_sample.py` → `backend/data/mymode.db`

## 4. API
| 요청 | 응답 | 담당 | 상태 |
| --- | --- | --- | --- |
| `GET /api/schedules/{senior_id}?date=YYYY-MM-DD` | `ScheduleResponse` = `{senior_id, date, items: [ScheduleItem]}` | B | **임시**: s1·12/1 예시만 돌려줌 |

`ScheduleItem`: `program_id, channel_id, channel_number, title, start, end, score, reason, kind(pick|fill)` — 시작 시각 순, 서로 안 겹침, 기상~취침 안.

화면은 서버 주소의 `/docs` 에서 직접 눌러볼 수 있음. 프론트 타입은 `pnpm gen` 으로 자동 생성 (`frontend/src/shared/api/rest.ts`).

## 5. 하루표 엔진 규칙 (B · 1단계 구현 기준)
| 단계 | 규칙 |
| --- | --- |
| 취향 추정 | 시청 기록에서 14일 반감기, 5분 미만 무시, 다음에 −0.3 / 됐다 −0.5 |
| 콜드 스타트 | 기록 비중 = 시청 횟수 ÷ (시청 횟수 + 10). 나머지는 첫날 정보(`seed_prefs`) |
| 점수 | 0.30 시리즈 + 0.25 출연자 + 0.15 장르 + 0.15 시간대 습관 + 0.10 새 회차·생방송 + 0.05 가족 추천 − 감점 |
| 제외 | 점수 0.35 미만, 기상 전·취침 후 |
| 배치 | 가중 구간 스케줄링(DP) — 겹치지 않게 점수 합이 최대가 되도록 |
| 빈 시간 | 20분 미만이면 유지, 점수 차 0.1 이내면 채널 유지 (`kind: fill`) |
| 고른 이유 | 가장 크게 기여한 항목으로 한 줄 (예: "송미란 님이 나와요") |
