## 개발 방식 (노트북 한 대로 개발·시연)
| 구분 | 결정 |
| --- | --- |
| 화면 | **webOS 앱이 아니라 웹(React)**. 1920×1080, 리모컨 키만으로 조작 (TV 호환 유지) |
| 채널 전환 | **화면 안에서 가상으로만**. 실물 TV·셋톱 제어는 발표에서 구조로 설명 |

| AI | 어댑터로 **fake / OpenAI / Claude** 갈아 끼움 (기본 fake, 키는 `backend/.env`) |
| 편성 데이터 | iptv-org/epg(XMLTV) + TMDB 출연진. 안 되면 CSV |
| 음성 | 타입캐스트 vs 일레븐랩스 비교 후 결정 (팀원 목소리, 서면 동의) |
| webOS 시뮬레이터 | 선택. 'webOS에서도 실행' 화면 캡처용 |

## 3명 작업 방식
**영역은 나누고 → 약속은 먼저 → main에는 PR로만.** 담당 폴더표는 `AGENTS.md`, 약속은 `docs/약속.md`.

| 단계 | 할 일 | 끝 기준 |
| --- | --- | --- |
| 0 · 함께 | 뼈대 → 약속(DB·API) → 공통 샘플 | 3명 모두 자기 노트북에서 서버 `/docs`와 화면이 뜨고, 약속이 PR로 승인됨 |
| 1 · A | 편성표 받아 칸 확인 → DB 넣기·시리즈 키 → TMDB → 채널 번호표 | 실제 하루치 편성표가 채널 번호와 함께 DB에 들어감 |
| 1 · B | 점수·배치·빈 시간 → 선호 계산 → 테스트 → 하루표 API | 샘플 어르신별 하루표 JSON과 추천 이유가 나옴 |
| 1 · C | TV 화면 뼈대 → 가상 시계·전환 → 가상 채널 전환 → 음성 비교·`/api/tts` | 가짜 하루표로 팝업부터 전환·음성까지 한 번 돎 |
| 2 · 함께 | 화면 ↔ 엔진 ↔ 실제 편성표 연결 | 시연 흐름이 처음부터 끝까지 돎 |
