# 명세 반영 대기 (B · 하루표 엔진)

> `docs/명세.md` 는 팀원 정리본(main)이 기준이다. 아래는 B 가 ②-2~②-4 에서 바꾼 **DB 칸·샘플·엔진 규칙**으로,
> 코드(`backend/app/models/db.py`, `backend/app/engine/`, `data/sample/`)에는 이미 들어가 있지만 명세에는 아직 반영되지 않았다.
> 3명 확인 후 `docs/명세.md` 에 PR 로 옮긴다 (그때 이 파일은 지움). 합격 기준·우선순위는 `QUALITY.md`, 결정 이유는 `PLAN.md` "결정 기록".

명세와 다른 점 요약
- 2절 DB: `programs.cast_roles·episode`, `seniors.fixed_breaks`, `watch_logs.end_reason`, `user_rules.kind` 에 `unpause`, 새 표 `plan_versions`, `plan_items.start·end`, `pref_source` 는 child/self/none (age_default 없음)
- 3절 샘플: s1 하루 종일 켜 두는 분 / s2 정해진 시간만 보는 분 / s3 자녀가 고른 관심사 + 기록 거의 없음
- 6절 엔진 규칙: 1~15 (TV 켜짐 패턴, 대표 방송, 다양성, 새로 추천, 신호 보강, 빈 시간 채우는 순서 등)

## 2. DB 표 (SQLite + SQLAlchemy)
| 표 | 한 줄 = | 주요 칸 | 채우는 사람 |
| --- | --- | --- | --- |
| `channels` | 채널 | `id`(예: KBS1), `number`(리모컨 번호), `name` | A |
| `programs` | 방송 한 편 | `channel_id`, `title`, `series_key`(회차 묶음), `genre`(대표 장르), `genres`(장르 전부, 비면 `[genre]`), `start`, `end`, `cast`(모르면 `[]`), `cast_roles`({이름: host/lead/regular/guest}, 없으면 무게 1.0), `episode`(회차, 모르면 null), `is_new`(새 회차), `is_live`(생방송) | A |
| `lg_contents` | 빈 시간용 LG채널·VOD | `title`, `genre`, `cast`, `duration_min`, `source`(LG채널/LG VOD) | A |
| `seniors` | 어르신 한 명 | `age`, `wake_time`, `sleep_time`, `pref_source`(child/self/none), `seed_prefs`({series, cast, genres}), `family_picks`, `fixed_breaks`(매일 비우는 시간 ["12:00-12:30"], 식사·약) | A (가족 화면) |
| `watch_logs` | 시청 기록 한 건 (**이 기기 안에서만 씀**) | `senior_id`, `series_key`, `genre`, `genres`, `cast`, `channel_id`, `started_at`, `watched_min`, `how_started`(chosen/continued/plan), `end_reason`(completed/skipped/help_cancel/channel_change/power_off, 없으면 completed), `cancelled`, `feedback`(기록용) | C (TV 화면) |
| `user_rules` | 음성 명령으로 생긴 규칙 | `kind`(exclude/pin/skip_today/rest_day/unpause — unpause = 반복 거절 쉬어가기 되돌리기), `target_type`(series/genre/none), `target`, `date`, `from_time`, `active` | B (음성 명령 API) |
| `plan_versions` | 하루표 변경 기록 | `senior_id`, `date`, `version`, `reason`, `changes`([{change: 추가/빠짐, program_id, title, start, why}]), `created_at` — 칸이 바뀔 때만 한 줄 | B |
| `plan_items` | 하루표 한 칸 | `senior_id`, `date`, `program_id`, `score`, `reason`, `kind`(pick/fill/lg), `start`, `end` | B |

- `how_started`: chosen = 직접 고름(말로 "KBS 틀어 줘" 포함) / continued = 앞 방송에서 그냥 이어짐 / plan = 하루표 추천으로 봄
- `pref_source` (첫날 관심사 출처) 우선순위: 자녀가 설치 때 부모님 관심사를 고름(child) > 본인이 고름(self) > 없음(none). **기본 장르는 두지 않는다** (관심사도 기록도 없으면 새 회차·생방송 + 시청 시간대만으로 짬)
- **시청 기록은 이 기기 안에서만 쓴다** (취향 추정·하루표 계산용. 밖으로 보내지 않음)

## 3. 공통 샘플 (`data/sample/`)
| 파일 | 내용 |
| --- | --- |
| `channels.json` | 채널 6개 (번호는 예시) |
| `programs.json` | 12/1 하루치 편성 92편. 채널마다 05:00~24:00 빈틈·겹침 없음 |
| `lg_contents.json` | LG채널·VOD 14개 (20~60분) |
| `seniors.json` | s1 김영숙(자녀 입력·트로트/드라마, **하루 종일 켜 두는 분**: 낮엔 KBS1 을 켜 두고 저녁에 드라마·트로트 몇 편, 켜짐 6~8시간), s2 박철수(본인 선택·뉴스/사극, **정해진 시간만 보는 분**: 아침 뉴스·낮 사극 재방송·저녁 시사·뉴스), s3 이순자(자녀가 고른 관심사 건강·교양·요리 + 기록 거의 없음 = 콜드 스타트) |
| `watch_logs.json` | 14일치 시청 기록. 5분 미만, 틀어만 놓은 긴 기록(continued — s1 낮 KBS1), 추천으로 본 기록(plan) 포함. 어르신마다 난수를 따로 써서 한 분을 바꿔도 다른 분 기록은 그대로 |
| `user_rules.json` | s1 "푸른 바다 이제 안 볼래"(exclude), s2 "저녁 뉴스 매일 챙겨 줘"(pin) |
| `schedule_example.json` | 하루표 API 응답 **모양 예시** |
| `genre_map.json` | 표준 장르 사전 초안 (표준 장르 13개 → 동의어·제목 키워드). 외부 편성표 장르를 바꿀 때 A 가 사용 |

- 방송 이름·출연자는 **전부 가상**. 실제 편성표는 A가 1단계에서 넣음
- 다시 만들기 `cd backend && uv run python scripts/make_sample.py` · 개발 DB에 넣기 `pnpm sample`
- DB 구조(`models/db.py`)가 바뀌면 옛날 DB 파일로는 하루표가 안 나옴 → `pnpm sample` 한 번 (화면에 안내 문구가 나옴)

## 6. 하루표 엔진 규칙 (숫자는 `backend/app/engine/config.py` 한 곳에. 합격 기준·우선순위는 `backend/app/engine/QUALITY.md`)
| # | 규칙 |
| --- | --- |
| 1 | **점수** = 0.30 시리즈 + 0.25 출연자 + 0.15 장르 + 0.15 시간대 습관 + 0.10 새 회차·생방송 + 0.05 가족 추천. 장르 = 장르 목록 중 가장 좋아하는 것. **출연자 정보가 없으면** 출연자 항목을 빼고 나머지 합(0.75)으로 나눔 (정보가 없어도 만점 가능, 출연자 선호 0 인 방송보다 손해 없음) |
| 2 | **신호 세기**: 직접 고름 100% · 이어짐/추천으로 봄 30% · 5분 미만·취소 0% (틀어만 놓기, 추천만 보다 좁아지기 방지) |
| 3 | **본 날 기준 반감기**: TV를 본 날 14일 (매일 보는 분·주말만 보는 분 공평). 장르가 여러 개인 기록은 각 장르에 같은 무게. 60일 넘은 기록은 버림. 기록이 적으면 첫날 관심사 비중↑ (기록 비중 = 횟수 ÷ (횟수 + 10)). 관심사를 바꾸면 다음 하루표에 바로 반영 |
| 4 | **음성 명령은 규칙**: exclude는 절대 제외(채우기·LG·새로 추천 포함, 장르로 뺐으면 장르 목록 중 하나라도 맞으면 제외), pin은 항상 포함(시청 시간대 밖이어도. 먼저 넣고 그 시간만큼 시간 상한에서 뺌. pin끼리 겹치면 점수 높은 쪽), skip_today·rest_day는 그날만 |
| 5 | **배치(DP)**: 기상~취침 사이에 **시작**하는 방송(끝나는 시간 무관), 점수 0.35(기준점) 이상, 하루 시간 상한 안에서 "(점수 − 기준점) × min(방송 길이, 60분)" 합이 최대가 되게 겹치지 않게. **같은 시리즈는 하루 1번**. **예외**: 0.35 를 넘는 방송이 6개 미만이면 기준점을 6등 점수까지 낮춤 (첫날에도 하루표가 비지 않게) |
| 6 | **빈 시간** (방송 사이, 하루 첫 시청 구간 시작~첫 방송, 마지막 방송~취침): 그 시각 TV 켜짐 **높음** → 배경 편성(앞 채널 이어서, 없으면 평소 켜 두는 채널, 끊기면 취향 LG — 이유 "평소 이 시간엔 TV 를 켜 두셔서 … 이어서 틀어 드려요") / **중간** → 20분 이하로만 / **낮음** → 비움(확인 화면 "쉬는 시간"). 같은 시리즈면 이어 붙이지 않음. LG 는 취향 점수 ≥ 기준점×0.8(새로 추천 1개 예외), 하루표 전체 시간의 30% 이하, LG 칸 수 < 방송 칸 수, 이유에 취향 근거(좋아하는 출연자·장르) |
| 7 | **하루 틀 = TV 켜짐 패턴** (신호 세기와 상관없이 켜져 있던 시간 전부, 5분 미만·취소만 제외): 시청 시간대 = 켜짐 비율 0.25 이상인 시각 — pick 은 그 안에서 **시작**하는 것만. 하루 전체 상한 = 하루 켜짐 시간 평균, 방송(pick) 상한 = 직접 고름·추천으로 본 시간 평균. 예산이 모자라면 켜짐 '높음'에 걸친 방송부터. 틀어만 놓던 시리즈는 방송 칸이 아니라 배경 편성 후보. 기록 있는 날 7일 미만이면 패턴 모름 → 기상~취침 전부 '중간', 240분. 점수가 같으면 시작이 이른 방송 먼저 |
| 8 | **오늘의 대표 방송**: 시리즈 취향 1위(0.5 이상)의 새 회차가 시청 시간대 안에 있으면 먼저 넣음. 이유 "오늘 꼭 챙겨 보실 ○○ 새 회차예요". 시간 상한엔 포함, 장르 비율엔 제외 |
| 9 | **다양성**: 한 장르 ≤ max(50%, 그분 실제 시청 비율) (대표 방송·챙겨 줘 제외, 셀 칸 2개 이상일 때), 같은 장르 3연속 없음 — 넘치면 그 장르에서 가장 약한 칸·3연속 줄의 칸 무게를 ×0.7 하고 다시 배치(최대 20번) |
| 10 | **채널 유지**: 앞 칸과 같은 채널에 거의 비슷한 방송이 있으면 그걸로 (점수 +0.05 가산해 비교) |
| 11 | **새로 추천 1칸**: 가장 좋아하는 장르와 가까운 장르(`NEAR_GENRES`) 중 시청 기록상 거의 안 본(5% 미만) 장르. 배치 뒤 남은 시간·자리에 방송, 없으면 빈 시간의 LG (이 LG 1개는 취향 점수 기준 예외). 이유 "새로 추천해 드려요 — …" |
| 13 | **같은 회차 하루 1번**(회차 정보 없으면 같은 시리즈 1번) · **채널 번호가 없는 방송은 넣지 않음** (기준표 v4 M4·M8) |
| 14 | **신호 보강** (②-3): 시리즈 점수 × 완주 추정 가중치(끝난 이유 별: 끝까지 1.0 / 전원 끔 0.7 / 채널 돌림 0.4 / 건너뜀 0.2 / "됐다" 0.1). 출연자 점수 × 역할 무게(진행·주연 1.0 / 고정 0.6 / 손님 0.3). 고정 비움 시간에 시작하는 칸 없음. 14일 안에 같은 시리즈를 건너뜀·"됐다"로 3번 끝내면 7일 쉬어가기(출연자 점수는 그대로, 확인 화면에서 되돌리기 = user_rules unpause). 시간대 습관은 1시간 단위(기록 적으면 4구간) |
| 15 | **빈 시간 채우는 순서·동점·이미 시작한 방송** (②-4): 켜짐 '높음' 빈 시간은 그 시각 방송 중 ① 하루표에 있는 시리즈의 다른 회차 → ② 좋아하는 출연자 → ③ 좋아하는 장르 → ④ 시간대 습관(그 시각에 평소 켜 두는 채널) → ⑤ 취향 하한을 넘는 LG → ⑥ 채널 유지. 점수 차 0.1 이내면 지금 채널의 다음 방송. 이미 시작한 방송은 남은 시간이 절반 이상·15분 이상일 때만. 하루표가 다시 만들어져 칸이 바뀌면 `plan_versions` 에 기록 |
| 12 | **취향을 모를 때**(관심사·기록 둘 다 없음): 새 회차·생방송만, 이유 "아직 취향을 몰라서 새로 하는 방송 위주로 골랐어요" |
